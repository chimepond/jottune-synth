# algorithms.txt: the 32 DX7 algorithms and the 8 OPM/OPN connections
# (CON 0 to 7) as routing tables. They feed the engine's route statement
# through tools/music/dx7_import.py. See docs/INSTRUMENT.md for authoring.
#
# The format: one block per algorithm, a line per field, blank lines and
# lines starting with # ignored.
#
#   algorithm NAME     dx7-1 to dx7-32, opm-0 to opm-7
#   ops N              6 for the DX7, 4 for OPM and OPN
#   carriers OP...     the operators whose outputs the voice sums
#   edge FROM>TO...    FROM's output modulates TO's phase; one or more
#                      pairs a line, any number of lines, none at all for
#                      an algorithm without modulation
#   feedback OP        the operator whose feedback the voice's feedback
#                      level sets
#   note TEXT          what the routing is; note lines join with a space
#
# Operators are numbered as the chips' own diagrams number them: DX7 OP1
# to OP6, every edge running from a higher number to a lower one; OPM and
# OPN OP1 to OP4 in the diagrams' order (OP1 = M1, the one with the
# feedback, OP2 = C1, OP3 = M2, OP4 = C2), every edge running from a lower
# number to a higher one. Both chips' registers list the slots in
# another order, M1, M2, C1, C2 (OP1, OP3, OP2, OP4 here, the OPN's 1,
# 3, 2, 4); the table follows the diagrams.
#
# Feedback: the engine's feedback is an operator's own (FEEDBACK_Q10 on
# every operator of a routed patch). The DX7's dx7-4 and dx7-6 feed a
# carrier's output back to OP6 through two or three operators; the table
# names OP6, and dx7_import.py gives OP6 that feedback as its own and says
# so in the block it writes.
#
# To the engine: dx7_import.py numbers the operators it keeps for the
# route statement so that every edge runs from a higher engine operator to
# a lower one, a forward edge, which the engine evaluates in the same
# sample as the chips do: engine op 0 first, then repeatedly the
# lowest-numbered operator left whose kept targets all have engine
# numbers. CARRIERS is the mask of the kept carriers' engine numbers and
# every kept edge has weight 256 (unity), since an operator's output level
# becomes its INDEX_Q10.
#
# The reduction rule, for an algorithm with more operators than
# the engine has (FM_OPS = 4) or than --ops asks for: keep the
# carriers (at most 4), keep the modulators by depth order, drop the
# deepest modulators first, and name every dropped operator in the
# generated block's comment. In detail, as dx7_import.py applies it:
#
#   1. An operator at output level 0 is silent and drops first, unless
#      every carrier is at 0; then the lowest-numbered carrier stays.
#   2. Carriers beyond the limit drop quietest first (the lowest output
#      level, then the higher operator number).
#   3. A modulator's depth is the length of its shortest path to a kept
#      carrier (1: it modulates a carrier). Modulators are kept by rising
#      depth while room is left; at one depth the louder (the higher
#      output level) goes first, then the lower operator number.
#   4. An operator with no path left to a kept carrier drops, and every
#      edge from or to a dropped operator goes; a dropped operator's
#      feedback goes with it.
#
# The 2-operator lines (dx7_import.py's `# pair:` comment lines, the
# form the engine plays without a route) come from the whole voice
# before the reduction, so --ops never changes them. The carrier line
# is the loudest carrier that sounds (as step 1 counts them; at equal
# output levels, one that a sounding operator modulates goes first,
# then the lower number); the modulator line is the loudest sounding
# operator with an edge to it (the lower number of equals), or a silent
# modulator when no sounding operator modulates it. The modulator line
# carries the voice's feedback when its operator is the feedback
# operator, whether or not the reduction keeps that operator.
