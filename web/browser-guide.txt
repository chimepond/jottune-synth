JOTTUNE SYNTH — BROWSER AGENT CARD

Write one complete JotTune Timeline (.tl) as readable text. example.tl is a
minimal sine diagnostic, not a composition to publish. Start a song with
authoring.txt and starter.score.json instead. The song must replay without source parts or
metadata files. instrument.txt is the instrument reference; its Python
composition, recipe search and CLI/MCP examples run outside this page.
The page has no Python runtime, external LLM API or telemetry. Its ordinary
composing and listening tools require no external AI/API key.

bottom of Sections, starts enabled: Load moves to Player, successful Play moves
to Live views, and natural completion returns to Songs. Manual section navigation,
including scrolling into another section,
turns it off and says so; select Auto move or Turn Auto move on to restore the

Saved versions are named separately from computed listening profiles. Favorites
defaults remain editorial; Browse all prefers the existing saved

Genre and tempo cite retained scores or creator declarations. Missing fields
remain Unknown, including model attribution. A BPM range is not a timed tempo
map. Catalog metadata binds only to its exact canonical version; portable

Collection summaries use this website selection, one Original per composition,
and show known/unknown denominators. They are not exchange or benchmark counts,
and construction/declarations do not measure musical quality or model progress.

Inspect notes reads only the selected TL using the installed native reader and
native events in a separate worker. It reuses the player's piano-roll geometry,
includes a text summary, and neither renders audio nor verifies a saved audio hash.
Selection changes abort its fetch/worker. Browsing and inspection cannot replace
or pause the loaded song; only Load song prepares a new audition. No inspection
runs merely because a filter changes or the page scrolls. After inspection the
button becomes Hide notes, which closes the preview without changing playback.

Song structure describes the complete native note commands. The Player's compact
panel describes the loaded song; Inspect notes shows a separate profile for the
selected song without changing playback. Duration, note attacks per second,
active/allocated voices, commanded frequency range, mean/maximum open gates and
time with no open gates come from native events, without another audio render.
Pitch changes do not count as new attacks; allocated voices may never play.
These are command facts, not musical-quality scores, audible pitch or measured
silence: releases and effects can continue after gates close. Use Analyze audio
for loudness, peaks and other waveform measurements. Incomplete or oversized
native listings explicitly report unavailable instead of partial statistics.

The Player names the loaded title and saved or computed version. On compact
screens the same identity, Play/Pause, time and Choose song stay visible while
scrolling. Successful preparation says Ready. Press Play to listen; technical hash and block
independence results remain in record details. Save song (.tl) keeps the complete
reopenable record; Save audio (.wav) keeps rendered audio. Downloads use safe,
titled filenames. Save and exact-version share actions precede the live views.

IntFM.recipes() lists native presets. IntFM.recipe(name,patch,tweaks) expands
named carrier-level tweaks; IntFM.recipeGain(name,patch,gainDb) adjusts all
carriers together and returns complete native declarations. See authoring.txt. await IntFM.compose(score,{release})
compiles existing score v1 into draftText with exact rendererRelease, sourceMap
and advisories. It does not render, change the editor, play or publish.
authoring.txt explains musical time and full native instrument declarations.
The browser and site Node client's score helper accepts score v1; local score
v2/v3 helpers are separate tools described in local-tools.txt. All routes can
render full native TL within their stated limits. Retain the exact editable

Before composing, preserve score.metadata.license in revisions and canonical
exports. For an original contribution whose author approved CC0, explicitly set
metadata.license to "CC0-1.0". Never silently relicense another work. This field
supplies no separate publication or CC0/dataset/rights/age/history consent;
private drafts may omit it. Use license, not licence, in portable TL metadata.

Optional score-v1 part audition: await IntFM.compose(score,{soloStreams:['lead']})
or {muteStreams:['bass']}; use one option only, with distinct existing stream
names. The complete original is compiled and natively inspected first. The
helper keeps all declarations, voices, length, spatial/effect/control events,
then removes only note/on/off gates excluded by the stream selection. It
refuses generators and any voice with gates in both retained and removed
streams, rather than changing ambiguous shared ownership. Render its draftText
normally. The returned selection describes the affected gates and scope.
Browser selection also natively inspects the derived draft before returning it;
this is validation, not audio verification. Its source-map pointers and advisory
indices still refer to the original score. Listen or Verify remains a separate call.
This measures a new performance through the effects, not independent additive
stems of the original: shared returns, dynamics and preceding audio can change.
To compare each part through the effects in a named passage, render solos in
sequence. Choose sections within the score duration. For example:
  const sections = [{name:'opening',startSeconds:0,endSeconds:1}];
  const rows = [];
  for (const stream of score.streams) {
    const d = await IntFM.compose(score, {soloStreams:[stream]});
    const t = await IntFM.listen(d.draftText, {release:d.rendererRelease});
    if (t.verdict !== 'valid') throw Error(t.stderr || t.verdict);
    const a = await IntFM.analyze(t, {sections});
    for (const s of a.pcm.sections)
      rows.push({stream,section:s.name,lufs:s.loudness?.integrated_lufs ?? null});
  }
  console.table(rows);
Each solo starts with the full score duration and its own effects history.
Shared dynamics and sends can respond differently with all streams playing.

The CLI equivalent is compose --solo-streams '["lead"]' or --mute-streams '["bass"]'.

Save draft text keeps the exact editable text, even before it is valid.
Verify saved render explicitly replays the current accepted canonical output
under its selected release. Editing retains the selected release but invalidates
old PCM and record identity; it never repairs a hash.

await IntFM.analyze(result=IntFM.result(),options={}) measures cached PCM in a
separate worker, without changing the result or starting playback. Options:
windowSeconds, sections:[{name,startSeconds,endSeconds}], dryVoices:true or
[0,1], dryMaxBytes, dryTimeoutMs, timeoutMs (default 120000, max 300000).
IntFM.cancelAnalysis() cancels it. Edits/new renders also cancel old analysis.
The result contains pcm, events and optional dry measurements plus the exact
recordSha256, pcmHash and rendererRelease. Optional dry failure is labelled;
a timeout cannot invalidate prepared audio. See analysis.txt for scopes/limits.
Record details → Audio measurements → Analyze audio measures the whole mix by
default. Analysis options adds a named section or dry source levels. Leave dry
levels off unless you need pre-effects levels and the additional native render
fits the UI's 128 MiB and 10-second dry budgets. For an explicit API budget,
see the frames × all voices × 4 byte check and dryTimeoutMs in analysis.txt.
Save analysis JSON keeps the full report. The API supports up to 32 sections.

Optional WebMCP in a supporting browser
Give intfm_compose {score: SCORE_V1} and optionally release. The tool composes
in this tab, verifies the saved TL and returns the title, a compact summary and
the first TL chunk. Its verified link pins the renderer release. Read url when
present. When urlBytes is present but url is null, request the link as chunks.
If urlError is present, deliver the TL file. To get chunks call the same tool
with {documentSha256,format:"tl"|"link",offset}. Start at 0 for a link or use
the previous chunk's nextOffset. Decode each chunk's base64 separately, join
the bytes in order, and check payloadSha256. Stop at nextOffset:null.
Use intfm_render for an existing TL. No tool starts playback or submits a song.
IntFM.describe().webmcp reports each tool's registration state. If your
assistant cannot see these browser tools, use the phone or Node workflow.

Call window.IntFM.describe() for capabilities, limits and reference URLs.
await IntFM.render(recordText, {mode:'verify', release:'RELEASE-ID'}) uses the
trusted installed registry. Both options are optional: verify is the default;
bare TL uses the default installed renderer and still must match its saved hash.
IntFM.verify(text, options) and IntFM.listen(text, options) select their modes.
IntFM.cancel() cancels pending rendering. IntFM.result() returns the visible
result. IntFM.clear() stops rendering/playback and clears the text and result.
The buttons and agent calls use the same implementation.

Optional render profile: {profile:{halfWidth:60,mirror:false}} computes Keys
on this device. Available half-widths are 30,45,60,75,90 degrees per side;
60 means a total 120-degree spread. It verifies the original source, uses the
native reader/renderer to replace spatial layout with pitch-based ordinary
stereo, levels the result and verifies the derived canonical record. It never
silently falls back to another engine when an archived build lacks conversion.
sourceRecordSha256 identifies the original canonical source; recordSha256 and
pcmHash identify the derived song. A source without a saved hash is not proof
of saved-hash agreement. Read result.profile for the conversion details.
This changes placement and carrier levels, not the authored note schedule; it
is not binaural HRTF rendering. The input file is never rewritten. The UI's
Prepare profile starts from its retained loaded source, never the last projection;
Keep loaded version restores it. Edits or loading another song reset that source.
Profiles default to strict levelling. Explicit levelPolicy:'carrier-bound'
permits a non-silent, unclipped result below target only when the shared carrier
gain limit is reached; profile.targetMet=false labels that exception. The UI
exposes it as an unchecked recovery option in the profile explanation.

Verify performs two renders. Listen performs one and reports
block_indep=unchecked. Listen API calls render PCM without starting audio;
the human Listen button prepares Web Audio during its click, then renders and
plays. Play auditions existing PCM. A separate user gesture is needed for audio.
The human song/file/drop/example/link controls render once when loading finishes,
without creating an audio context. Play becomes enabled after an audible result;
it starts playback on its own click. Loading progress and Cancel sit beside Play.
Pasting or editing text invalidates the prepared audio; Listen renders and plays
those changes. Programmatic IntFM.loadLink remains load-only.
await IntFM.prepareLink(url) loads and silently prepares playback as one
cancellable operation, preserving the link's release and expected identity.
It returns a listener result; inspect verdict as with render. Network errors
and cancellation reject. It never starts audio or acquires an audio device.

For an automation reply, IntFM.summary(result=IntFM.result()) returns a compact
JSON-safe object with current result identity, verification and dimensions; it
contains no PCM arrays or native event rows. IntFM.toText(result) returns the
canonical full TL document as a string, preserving its validated metadata.
Use it instead of manually decoding result.canonical.

await IntFM.toLink(result, {pinRelease:true}) returns a URL string exactly as the
player's song-link share control builds it. pinRelease defaults to true. It
uses the same compact library reference or portable TL fragment as that control;
it does not publish or upload the song. Keep the returned string intact and
save the TL file too.

For a measured report, open Record details → Audio measurements → Analyze audio
after verification. Wait for analysis to finish, then choose Copy report for your
agent. If preparation fails, the same report button returns the input error.
The report includes the native sample peak, peak and RMS in dBFS, sample frames
and saturation count in song.play. Completed analysis adds integrated LUFS,
stereo balance and exact ending silence. The clipboard includes up to eight
named sections, dry streams and authoring advisories each, with total counts.
Save analysis JSON keeps all measured windows, channels, sections and optional
dry levels. Copying a report does not start or interrupt analysis.

A result includes verdict, code, mode, verified, verification, native stdout and
stderr, canonical Uint8Array bytes, recordSha256, pcmHash, engineIdentity,
engineId, rendererRelease, development, play/metrics objects, PCM Int16Array,
sampleRate, channels and native events. Integer result fields remain decimal
strings, preserving values above 2^53. Rendering happens in a dedicated Worker.
A completed result also dispatches window's intfm-result event with result in
detail, for a host page integrating the workbench.
An intfm-invalidate event announces edits, clearing or a new render; its detail
is null and the prior result must no longer be used as current audio or analysis.

Verdict valid means the native render succeeded. verified=true requires full
verify, match=yes and block_indep=yes. A listener can match its checksum while
block independence remains unchecked. A draft without an expected hash can
render valid with match=-, but is not labelled verified. Its canonical download
contains the computed hash; replay that single file to verify the saved record.
Computing a hash during Listen does not perform that independent replay. Thus
a Listen result can contain canonical TL and pcmHash while verified stays false.
Refused carries the native diagnostic. Wrong PCM hashes or unavailable/withdrawn
explicit releases are mismatch, never a fallback or a newly sealed success.

Record SHA-256 covers the canonical native music body; a full-document checksum
also covers metadata. PCM hash is the engine's FNV-1a 64 value, not SHA-256. Device audio resampling is outside that identity. Raw amb1
and amb3 channels are field coefficients: inspect/export them, not speaker audio.

For a text-only browser session, send the editable score and the verified playback

  await IntFM.exportChunk(saved, {format:'tl', offset:0, bytes:6000})
Use format:'link' for the UTF-8 bytes of the pinned URL from IntFM.toLink(saved).
Defaults are 'tl', offset 0 and 6000 bytes. Each request accepts 1..7200 bytes.
Decode each reply's base64 separately and verify its chunkSha256. Request the
nextOffset from that reply until it is null. Keep format, totalBytes,
documentSha256 and payloadSha256 constant. Concatenate the decoded bytes in
offset order, check totalBytes and verify the complete payloadSha256. For TL it
must equal the saved documentSha256. Decode UTF-8 only after joining chunks.
An offset at totalBytes yields an empty final chunk. Export runs locally and
preserves the render's verification status. Attach audio when file transfer is
available, and label playback that nobody auditioned as unheard.

await IntFM.loadLink(url) loads without rendering. It accepts a plain CORS-enabled
TL URL, #v1.<base64url(zlib-deflate(record))>, legacy #r=<sha256>, library
references #song=<encoded songs/filename.tl>&sha=<sha256>, and service
links under the application's path prefix: r/<sha256> and s/<submission-id>.
Those service links require api/records/<sha256> or api/submissions/<id> to
return {record_sha256, renderer_release, record_url}. record_url stays within
that service's origin and prefix. Rendering checks the requested canonical hash.
The static workbench includes no publishing service. The legacy #r form reads
r/<sha256>.tl directly. ?release= names an exact registry entry; a conflicting
service descriptor is refused. Unrelated anchors such as #agent do not load TL.

Same-origin iframe protocol:
parent.postMessage({protocol:'intfm-v1', id:'request-1', operation:'render',
                    args:[text, {mode:'verify', release:'RELEASE-ID'}]}, location.origin)
Reply: {protocol:'intfm-v1', id, value} or {protocol:'intfm-v1', id, error}.

Browser profile: at most 1,000,000 UTF-8 TL bytes and 300 seconds of audio;
duration comes only from the native reader. Operational limits are 16 MiB of
engine output, 120 seconds per Worker, 20,000 drawing events and 256 MiB Wasm
linear memory. Native preflight gives a lower bound, with separate one-render
and verification estimates; the page reserves PCM/playback copies too. This is
not a bound on the whole tab. The local CLI is available for larger records.

Renderer releases are selected by registry release_id/id, never executable URLs
inside TL. Missing or withdrawn explicit releases cannot use the default.
Development builds are labelled separately; their artifact IDs are not kept
release IDs. Kept releases retain their runtime/shim. Engine lines describe
knobs/tables and do not uniquely identify source revisions.

STATIC CHECKSUMS AND THE KEPT WASM CONTRACT
agent-manifest.json lists each downloadable static artifact's relative path,
SHA-256 and byte count. engines.json selects renderer releases and their Wasm,
runtime and library checksums. The official Node client checks cached/downloaded
assets against its selected manifest. To check the initially downloaded client:

  curl --fail --location "${SITE}agent-manifest.json" --output agent-manifest.json
  node --input-type=module - <<'JS'
  import {readFileSync} from 'node:fs';
  import {createHash} from 'node:crypto';
  const manifest = JSON.parse(readFileSync('agent-manifest.json', 'utf8'));
  const entry = manifest.files.find(item => item.path === 'agent.mjs');
  const bytes = readFileSync('agent.mjs');
  if (!entry || bytes.length !== entry.bytes ||
      createHash('sha256').update(bytes).digest('hex') !== entry.sha256)
    throw Error('Client differs from the downloaded manifest.');
  console.log('Client checksum matches the downloaded manifest.');
JS

These same-origin hashes detect differences from the manifest; they do not
authenticate that manifest independently or make downloaded code trustworthy.
The browser checks renderer Wasm and a fetched runtime wrapper against the
registry, then loads that wrapper and its relative shim imports through normal
same-origin module loading/cache. Those imported responses are not independently
bound to the fetched wrapper bytes. Packaging preserves the complete archived
shim, but only the Node client's verified loader checks each actual transitive
import against the manifest. Both clients still trust their initial site/client.
For the supported offline workflow, use agent.mjs setup and retain the complete
cache. agent-start.txt describes its network requests and execution permissions.
The Node client requires kept releases by default. Add --allow-development only
when intentionally using your own source build; reports retain that distinction.

The kept harness.wasm is a WASI preview1 command module: its host imports come
from wasi_snapshot_preview1 and its entry exports are memory and _start. It
accepts native CLI arguments/files through WASI; it is not a JavaScript API
with an exported render(song) function. The browser companion has additional
PCM access exports and is a different artifact. Use the official client or
window.IntFM to manage the correct module, host filesystem, lifecycle and
selected release. A replacement WASI host is not a workaround for an external
execution-policy refusal; the supplied workflow must be authorized there.

The app works beneath a path prefix. Hosted r/ and s/ pages need a base URL
pointing at that app prefix. The service worker is scoped there, caches the app
and used engine assets, and does not cache live service records/API responses.
Offline installation starts in the background and never delays online rendering.
After 15 seconds a slow installation is labelled still running; a late result
updates the footer. Unsupported or failed setup leaves online playback available.
An uncontrolled first render may not cache its renderer: load the song again
online after offline support becomes ready. Cancel remains immediate.
It refreshes the registry online; offline revocation status may be stale.
Save TL locally: browser caches can be evicted and are not a backup.
Actual Safari/iPhone, Firefox and offline acceptance remain pending until run.

Optional Node smoke bridge from a source checkout (not a browser UI test):

It invokes the same Worker logic. A new canonical output is written only for a

Portable TL documents
---------------------
A TL may start with a bounded `# jottune-tl 1 1` metadata header. See
`tl-format.txt` for its exact fields, version rules and limits. Keep that header
with the native body when saving/sharing the file. Canonical music-body SHA-256
is the song identity; document SHA-256 additionally covers metadata bytes.
The current TL and engine compatibility counters are both 1; newer required
versions are refused. Existing headerless files remain valid. Score JSON may
include an explicit metadata object; unknown model/genre/tempo stays unknown.
Metadata declarations never replace explicit publication consent. name/about/mark
are authoring comments and disappear from canonical output; use metadata.title
for the durable title. The portable field is license (not licence); the WAV
provenance key licence above is a separate interface. Use "license":"CC0-1.0"
for ChimePond/tunes publication only with the author's explicit authorization.
It supplies no actual CC0, dataset, rights, age or history-retention consent,
and no permission to publish. Local private drafts may omit a license.

Player Facts shows the TL version, engine compatibility version, header status
and embedded declarations. Headerless files show the inferred legacy version 1.
Catalog Load and Notes inspection verify the complete file against its document
checksum, or its existing file/song checksum for older catalogs. Body-based song
IDs stay unchanged. Standalone links remain usable offline; catalog labels found
later are attached only when their complete-file checksum also agrees.
